# БибиЗадачи — новый бот заданий и бибибонусов

Отдельный бот и мини-приложение (НЕ трекер смен). Здесь пользователи из
группы подают заявку, берут задания на карте, выполняют их и получают
бибибонусы на бесплатные поездки. Дизайн и концепт взяты из рабочего
трекера смен, механика — новая.

## Файлы

| Файл | Что это |
|---|---|
| `main.py` | Код бота — точка входа (это запускает хостинг) |
| `index.html` | Страница мини-приложения (отдаётся по адресу сайта) |
| `requirements.txt` | Зависимости |
| `.gitignore` | Не даёт загрузить в GitHub базу, кеш и секреты |

Кладутся в корень **отдельного** репозитория, рядом.

## Запуск на BotHost

1. Создай на GitHub отдельный репозиторий и загрузи в его корень все пять
   файлов из этого комплекта.
2. В BotHost создай Telegram-бота с языком Python, вставь токен нового бота
   и подключи этот репозиторий.
3. В дополнительных настройках укажи:
   - главный файл: `main.py`;
   - «Использовать домен»: включено;
   - порт: `3000`.
4. В разделе «Переменные окружения» добавь `BOT_USERNAME` и
   `ADMIN_PASSWORD`. Сам пароль храни только в панели BotHost.
5. Запусти новый деплой. После запуска открой
   `https://твой-домен/health`: должен появиться ответ с `"ok": true`.
6. В @BotFather установи этот HTTPS-домен как URL Mini App/Menu Button.
   Для Direct Link используй короткое имя `app`.

BotHost сам передаёт токен как `BOT_TOKEN`, а выбранный порт — как `PORT`.
Код уже слушает `0.0.0.0` и автоматически хранит SQLite-базу в постоянной
папке `/app/data`.

## Почему это точно не столкнётся с трекером смен

Файлы называются так же, как у трекера, но конфликта нет:

- Новый бот лежит в **отдельном репозитории** — одинаковые имена файлов в
  разных репозиториях не пересекаются.
- Отдельная **база**: `bibitasks.db` (у трекера — `bibibike_work.db`).
- Отдельный **токен** и отдельный бот в BotFather.

Главное правило: заливать в **отдельный** репозиторий, не в тот, где трекер
смен. Данные трекера в полной безопасности.

## Переменные окружения (на хостинге)

Обязательные:
- `BOT_TOKEN` — токен НОВОГО бота от @BotFather (отдельный бот, не трекер смен)
- `BOT_USERNAME` — username бота без @ (для кнопок и реферальных ссылок)
- `ADMIN_PASSWORD` — пароль первого входа ответственных. Задаётся только
  в переменных окружения BotHost и никогда не записывается в `main.py`,
  `index.html`, `.gitignore` или GitHub.

Полезные:
- `ADMIN_IDS` — резервный список Telegram ID ответственных через запятую,
  например `111,222`. Эти люди получают роль сразу, без ввода пароля.
- `DATA_DIR` — менять не требуется: на BotHost код автоматически использует
  постоянную папку `/app/data`.
- `WEBAPP_SHORTNAME` — короткое имя Direct Link (по умолчанию `app`)
- `COMMUNITY_CHAT_ID` — ID группы сообщества (задел на будущее)
- `REFERRAL_MILESTONES_JSON` — необязательная настройка реферальных
  ступеней. Формат: `{"5":50,"25":500,"50":1500,"100":4000}`.
- `WITHDRAW_MIN` — минимальная сумма заявки на вывод, по умолчанию `1000`.
- `WITHDRAW_CONTACT` — Telegram username ответственного без `@`. После
  создания заявки Mini App открывает личный чат с подготовленным текстом.

Свой Telegram ID можно узнать у @userinfobot.

## Настройка в BotFather

1. Создай нового бота → получи токен → впиши в `BOT_TOKEN`.
2. Mini Apps → Main App / Menu Button / Direct Link → укажи домен хостинга.
3. Direct Link короткое имя — то же, что в `WEBAPP_SHORTNAME`.

## Как это работает

**Обычный пользователь:**
1. Открывает бота из группы (тема «Работа») → видит приветствие.
2. Жмёт «Открыть задания» → подаёт заявку (имя + телефон).
3. Ждёт одобрения (придёт уведомление в чат).
4. После одобрения — берёт задания на карте, выполняет, жмёт «Готово».
5. Ответственный подтверждает → бибибонусы падают в кошелёк.
6. От 1000 бонусов создаёт заявку на обмен на реальные бонусы приложения.
   Сумма резервируется, а Mini App открывает личный чат ответственного.

**Ответственный:**
- При первом входе выбирает «Ответственный» на экране регистрации и вводит
  серверный пароль. После успешной проверки роль закрепляется за его
  Telegram ID.
- Вкладка «Модерация»: одобряет заявки, создаёт задания, подтверждает
  выполнение, видит команду и балансы, начисляет/списывает бонусы вручную.
- В разделе «Команда» начисляет и списывает бонусы с обязательной причиной.
- В разделе «Выводы» подтверждает заявку либо отклоняет её. При отклонении
  зарезервированная сумма автоматически возвращается участнику.
- При создании выбирает режим задания:
  - **общее** — его видят все одобренные участники, забирает первый;
  - **персональное** — его видит только выбранный сотрудник.
  - **для всех** — карточку видит каждый участник и каждый может выполнить
    её один раз; проверки и начисления у всех независимые.
- Для обоих режимов можно указать начало и окончание рабочего слота.
- При персональном назначении сотрудник сразу получает сообщение от бота
  с текстом, адресом, временем и наградой.

Если ответственного ещё нет, принимать его заявку не требуется: правильный
пароль является первичным способом создать роль. `ADMIN_IDS` лучше оставить
как резервный доступ владельца на случай ошибочной настройки.

**Уровни доверия:** Новичок → Проверенный (10 заданий) → Амбассадор (40).
Растут за подтверждённые задания.

**Рефералы:** кнопка «Поделиться ссылкой» в профиле. Засчитываются только
одобренные друзья. Награды выдаются один раз при достижении ступени:

- 5 друзей → 50 бонусов;
- 25 друзей → 500 бонусов;
- 50 друзей → 1500 бонусов;
- 100 друзей → 4000 бонусов.

Значения можно заменить через `REFERRAL_MILESTONES_JSON`, не меняя код.

## Что готово и проверено

- Полный цикл: заявка → одобрение → задание → взятие → выполнение →
  подтверждение → бонусы (протестировано end-to-end).
- Общие и персональные задания разделены; чужое персональное задание нельзя
  увидеть или забрать прямым API-запросом.
- Массовое задание остаётся доступным всей команде, но повторное выполнение
  одним пользователем блокируется уникальной записью.
- Реферальные ступени и массовые задания защищены от повторного начисления.
- Одновременно у участника может быть только одна заявка на вывод.
- Вывод сначала резервирует баланс атомарной транзакцией: параллельный запрос
  не сможет зарезервировать ту же сумму второй раз.
- Повторное решение по одной заявке блокируется; отклонение создаёт отдельную
  возвратную проводку в истории кошелька.
- Слоты хранятся в UTC, а в Mini App показываются по локальному времени
  телефона. В сообщении бота время указывается по Москве.
- Защита: без подписи Telegram — отказ, поддельная подпись — отказ,
  неодобренные не видят задания и модерацию.
- Проверка прав выполняется на каждом рабочем и административном API-запросе;
  отказ нельзя обойти прямым обращением к endpoint.
- Античит-основа: задание нельзя взять дважды, все бонусы логируются с
  причиной.
- Повторное одобрение одной заявки или одного задания не может повторно
  начислить бонусы.
- Списание не может увести баланс участника ниже нуля.
- Веб-сервер стартует первым и не роняет бота.

## Что дальше (по плану платформы)

- Трата бонусов на поездки автоматически — когда появится интеграция с
  системой аренды Бибибайк (пока полуручно через промокод).
- Гео-проверка выполнения и фото — для дорогих заданий (Фаза 4 плана).
- Кнопка «Хочу помогать» для полностью посторонних — расширение за пределы
  сотрудников (Фаза 5). Сейчас заявку может подать любой, кто открыл бота.

## Важно

Это самостоятельный бот с отдельной базой `bibitasks.db`. Он никак не
пересекается с трекером смен — можно запускать параллельно, на разных
токенах. Данные трекера в безопасности.

Не вписывайте пароль ответственных ни в один файл репозитория. Добавьте
`ADMIN_PASSWORD` только в разделе переменных окружения панели BotHost.
