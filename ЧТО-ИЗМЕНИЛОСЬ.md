# БибиЗадачи v1.6.0

Заменить нужно два файла: `main.py` и `index.html`. База не ломается —
новые таблицы и колонки создаются сами, старые данные остаются на месте.

---

## 1. Твой доступ — без пароля

В `main.py` теперь зашито:

```python
OWNER_IDS = {7785586524}
ADMIN_IDS = _parse_ids(os.getenv("ADMIN_IDS", "")) | OWNER_IDS
```

Ты получаешь роль ответственного сразу при открытии приложения. Пароль,
переменные окружения и одобрение больше не нужны — и заблокировать себя
ты уже не сможешь, даже если случайно снимешь с себя роль в базе.

Вход по паролю остался как запасной путь для других людей:
`Профиль → Доступ ответственного`. Чтобы дать кому-то постоянный доступ
помимо интерфейса, вписывай ID в переменную `ADMIN_IDS` на хостинге, а не
в код.

Одно замечание: Telegram ID не секрет, но он останется в открытом
репозитории. Если это смущает — вынеси его в `ADMIN_IDS` на BotHost и
верни `OWNER_IDS = set()`.

## 2. Роли участников

`Модерация → Команда`. У каждого участника видна текущая роль и кнопка
`Роль` — открывается выбор из трёх:

| Роль | Что может |
|---|---|
| 🌿 Помощник | берёт задания, получает бибибонусы |
| 🚲 Сотрудник | то же, плюс пометка «штатный» в команде |
| 🛡️ Ответственный | заявки, задания, награды, обмены |

Роль меняется мгновенно, участник получает сообщение от бота. Три правила
защиты, чтобы не сломать себе доступ:

- свою роль сменить нельзя — только через другого ответственного;
- последнего ответственного понизить нельзя, иначе заявки повиснут навсегда;
- роль выдаётся только одобренному участнику — сначала прими заявку.

Заодно: персональное задание теперь можно назначить и ответственному
(раньше он выпадал из списка исполнителей).

## 3. Дизайн

Белый лист, зелёные плашки, чёрный текст — как на логотипе.

- Фон белый, карточки светло-зелёные с тонкой рамкой.
- На каждом экране одна **сплошная зелёная плашка-герой**: баланс в
  кошельке и уровень доверия в профиле. Чёрный текст на зелёном, как `bb.`
  на логотипе, и чёрная кнопка внутри неё.
- Один мотив на весь интерфейс: любой прогресс — это **шкала заряда** с
  бегущим разрядом. Уровень доверия, реферальные ступени, сколько осталось
  до обмена — всё одной визуальной логикой.
- Бибибонус измеряется молнией ⚡.

**Анимации не тронуты.** Все восемь keyframes перенесены байт-в-байт:
въезд плашек, разряд по шкале, вспышка по карточке задания, подскок
счётчика бонусов, подпрыгивание медалей, пульс следующей ступени, шторки.
Изменился только цвет свечения у счётчика — с тёмно-зелёного на брендовый,
иначе на белом фоне его не было видно. Движение осталось прежним.

Про оптимизацию: ни одного внешнего шрифта, ни одной библиотеки, ни одной
картинки — только тег Telegram SDK. Всё движение на `transform` и
`opacity`, то есть на GPU и без перерисовки страницы.
`prefers-reduced-motion` уважается.

## 4. Награды (из прошлой версии)

`Модерация → 🏅 Награды`. Свой каталог: значок, название, за что, бонус,
плюс переключатели «много раз / один раз» и «показывать в каталоге».
Разовая награда не выдастся дважды — это защищено уникальным индексом в
базе, а не проверкой в коде. Есть `Снять`: бонус вернётся и не уведёт
баланс в минус. В `Команде` у каждого кнопка 🏅.

Восемь наград уже засеяно: ⚡ Молния, 🛠 Мастер, 🌙 Ночная смена,
🏅 Спасатель, 📸 Глаз-алмаз, 🤝 Наставник, 👑 Легенда месяца,
🌱 Первое задание. Твои правки при следующем деплое не перезапишутся.

## 5. Что было починено попутно

- **WAL для SQLite** — без него параллельные «Взять задание» упирались в
  блокировку и отдавали 500. Плюс таймаут ожидания 15 секунд.
- **Обработчик ошибок на весь API** — любой сбой отдаёт JSON, а не
  трейсбек с пустой «Ошибкой» на экране.
- **Уведомления в фоне** — раньше рассылка админам шла внутри HTTP-запроса.
- **Валидация ID** — `task_id: "abc"` больше не превращается в 500.
- **Отклонённого можно вернуть** — раньше `reject` ставил `blocked`
  навсегда, без правки базы человека было не восстановить.
- **`prompt()` убран** — в Telegram WebView он работает не на всех
  клиентах, кнопка «Готово» могла молча не срабатывать. Вместо него
  своя шторка ввода.
- **Тупик со входом** — форма пароля жила внутри блока регистрации и
  исчезала после отправки заявки.

команда вырастет.
